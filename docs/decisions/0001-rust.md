# 0001 - Rust for core, CLI, TUI

Status: Accepted (2026-11)

## Context

Canopy must hold dozens of streaming agents with flat memory, no pauses, millisecond startup and zero idle CPU. It ships as one binary.

## Decision

Write the daemon, CLI and TUI in Rust. Runtime crates in use now (all licensed MIT and/or Apache-2.0 unless noted):

- `tokio` (MIT), features `rt, net, process, io-util, io-std, sync, time, macros, signal`, never `full`.
- `serde` (MIT/Apache-2.0), `serde_json` (MIT/Apache-2.0).
- `rusqlite` (MIT) with `bundled`; the bundled SQLite is public domain.
- `pico-args` (MIT), `ulid` (MIT), `anyhow` (MIT/Apache-2.0).

Approved for later milestones, not yet added: `ratatui`, `crossterm` (M4, MIT); `hyper`, `hyper-util`, `http-body-util`, `fastwebsockets`, `rust-embed` (M5, all MIT, `fastwebsockets` Apache-2.0).

`ts-rs` (MIT) is an optional feature of `crates/protocol`, enabled only by `make gen`. The PLAN's `log` was dropped: the daemon writes to stderr, which a detached daemon redirects to `daemon.log`. Release profile: opt-level 3, fat LTO, one codegen unit, panic abort, strip. No custom allocator until a profile says so.

## Consequences

No GC, flat memory, one static binary, `tokio` parks on kqueue/epoll so idle CPU is zero. Any new crate needs a new ADR with size, license and why twenty lines of our own will not do.

## Rejected

Go: GC and larger baseline, weaker modelling of the event enum. Zig: no production HTTP/WS/SQLite/TUI stack. TypeScript/Bun: 50-100 MB baseline RSS, and vendor SDKs only wrap the child-process protocols we can speak directly.
