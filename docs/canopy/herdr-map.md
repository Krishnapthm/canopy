## Layout

`Kind` is a serde-tagged `type`: Block, Row, Column, Stack; stacks select an active child and may have a header (`src/layout.rs:278`). JSON deserializes directly into `Node` in `load_layout` (`src/window.rs:927`); built-ins use the same representation (`src/window.rs:155`). Blocks carry terminal, mod, tab-context or agent content (`src/layout.rs:12`); nodes carry floating children separately (`src/layout.rs:370`), whose edge, alignment and reveal geometry are described by `Float` (`src/layout.rs:64`). Layout clicks, including float state, live separately from authored layouts (`src/layout_sync.rs:1`).

## Window and input

`AppWindow::render` composes the chrome tree, frame and overlays (`src/window.rs:4908`); `render_node` recursively produces GPUI flex rows/columns, stack selection, blocks, separators and floats (`src/window.rs:4068`). `render_block` mounts `shown_terminal` and updates model focus on mouse-down (`src/window.rs:4133`). Terminal keys, scroll and mouse handlers live on `TerminalView` (`src/terminal.rs:2226`, `src/terminal.rs:2238`), with selection drag listeners installed during prepaint (`src/terminal.rs:2313`). Root actions route bound commands (`src/window.rs:4964`); focus changes are reconciled each render (`src/window.rs:4914`). No `on_pinch` handler exists in app source; GPUI provides it (`vendor/gpui-pre/src/elements/div.rs:1072`).

## Terminal drawing and zoom

**Independent per-terminal scale: yes, since phase 4.** `TerminalView::set_scale` (`src/terminal.rs`) draws one terminal at a multiple of the global font size, cell size and padding. Every size read in the renderer goes through `font_px()` and `pad()`, which multiply the global value (`Look.font_size` composed in `src/window.rs`, `settings::font_size()` in `src/settings.rs`) by a thread-local scale set with the `Scaled` guard around render, prepaint and paint. Pointer coordinates need no division: `Grid::cell` and `Grid::origin` are the drawn ones, so `local()` and `cell_at()` map directly. A `rest` body size in world pixels fixes the PTY's columns and rows: what fits it at the drawn scale (`grid_at_scale`), frozen during a corner drag. `Vt` is untouched. Panes in tabs and pop-outs stay at scale 1.

## Model and core ownership

Spaces have a folder, optional machine, tabs and an active tab (`src/model.rs:32`); tabs have a layout tree, focus history and optional pane zoom (`src/model.rs:13`); a pane is a terminal block referring to a core address (`src/model.rs:568`). Core events supply terminal records (`src/hc.rs:58`), while per-machine layout documents are flushed through the window's document slots (`src/window.rs:1849`). **`terminal.open {place: "tab"}` creates one tab containing one pane with one terminal**, provided an active space exists: dispatch calls `new_tab` (`src/window.rs:3097`), which spawns once and adds `Tab::new` (`src/window.rs:2460`), whose root has one pane (`src/model.rs:110`). Terminals can exist outside tabs: `terminal.park` removes their pane while keeping them running (`docs/commands.md:143`, `src/window.rs:3114`). **`hc ls --json` exposes `parent` when non-null**: core `cli.rs:421` maps terminal records through `short`, whose retained fields include `parent` (`cli/output.rs:147`). The app also normalizes parent addresses from core events (`src/hc.rs:91`). This is source evidence, not an observed installed CLI response.

## Agent detection

The built-in program table is overlaid entry-by-entry by app-home `programs.json` (`src/programs.rs:1`, `src/programs.rs:173`). `of` resolves the reported status `app`, otherwise argv, into a program descriptor including `shell` and `agent` (`src/programs.rs:193`, `src/programs.rs:291`, `src/programs.rs:342`); launchable menu entries have `run` (`src/programs.rs:67`). Model agent records retain the program's 7501 word, app, turn and attention state (`src/model.rs:65`); incoming records feed these fields (`src/window.rs:2066`).

## Writing terminal input

**Arbitrary text is possible; input is not limited to the clipboard.** The public app command `terminal.paste` takes no text argument (`src/commands.rs:68`) and reads the clipboard (`src/terminal.rs:688`), but its underlying `Vt::paste_bytes(text)` accepts arbitrary strings, conditionally wraps bracketed paste, and does not append Enter (`src/vt.rs:1497`). The private view `send` passes bytes to public `Core::input(channel, bytes)` (`src/terminal.rs:630`, `src/hc.rs:512`). A new internal quote action can reuse those paths; `Vt::write` is received output, not PTY input (`src/terminal.rs:517`). Mods can execute `hc` via `herdr.hc(args)` (`defaults/herdr.d.ts:17`, `src/mods.rs:926`); the installed help says `hc send <t> <text>` pastes and presses Enter, so it is not by itself the plan's review-before-submit operation. No clipboard save/restore workaround is needed for an internal input implementation.

## Inspection commands

`commands` prints the local command registry without contacting a window; `ls` and `status` send one JSON line to the app-home `herdr-app.sock` (`src/control.rs:15`, `src/control.rs:80`). `ls` returns `world()`; `status` returns zoom, fonts, active space/tab, focus, layout, floats, overlays and error reports (`src/window.rs:3803`). With the dev window running these can later be used as `HERDR_APP_HOME="${TMPDIR:-/tmp}/canopy-dev/home" target/debug/herdr-app status` (or `ls`); none were run for this task.

## Isolation

**App home:** `HERDR_APP_HOME` overrides both XDG config and the default `~/.config/herdr-app` (`src/mods.rs:49`); it also relocates the app control socket (`src/control.rs:15`). The launcher sets it explicitly to `${TMPDIR:-/tmp}/canopy-dev/home` (`scripts/dev:8`). The macOS CLI-link installer skips an ordinary target/debug executable, so this path does not replace the installed CLI link (`src/core_bin/cli_link.rs:16`).

**Core session/socket:** the app spawns `hc connect` with inherited environment (`src/hc.rs:325`). Core `Paths::from_env` reads `HC_SESSION`, and `HC_SOCKET` wins over the configured socket (`paths.rs:17`, `paths.rs:27`); empty session defaults to `default` (`paths.rs:83`). The launcher fixes session `canopy-dev`, socket `<scratch>/c.sock`, and config home `<scratch>/config`, so neither inherited socket nor real config selects the real core (`scripts/dev:8`). Core normally autostarts through `connect_or_start` (`client.rs:76`); the launcher explicitly runs `server start`, which uses the explicit startup path (`cli.rs:551`), then requires the scratch socket to exist (`scripts/dev:26`).

**Core state:** core uses `$XDG_STATE_HOME/herdr-core/<session>` and `$XDG_CONFIG_HOME/herdr-core/config.toml` (`paths.rs:22`); Unix defaults, including macOS, are `~/.local/state` and `~/.config` (`platform/unix.rs:116`). Socket defaults use runtime/state paths, but explicit `HC_SOCKET` overrides these (`paths.rs:26`). Thus dev state is `<scratch>/state/herdr-core/canopy-dev`, separate even from a same-named session elsewhere (`scripts/dev:9`). Linux sandbox uses the same session/app-home/state separation (`scripts/sandbox:23`), plus a private Weston/Xwayland display (`scripts/sandbox:42`); dev reuses its environment approach, not its build or display startup.

**Lifecycle:** run `scripts/dev` only when ready to open the scratch window; close that window before `scripts/dev-stop`, since app reconnection could restart its core (`src/window.rs:811`). Running `scripts/dev` again while the reserved core still answers on its socket reuses it and only starts the app. Otherwise the reservation rejects duplicate launch, records the hc executable, and refuses an existing socket before starting (`scripts/dev:18`). Stop requires that reservation and addresses only the fixed scratch socket (`scripts/dev-stop:7`); core stop uses an existing connection without autostart (`cli.rs:805`). State and home remain for later runs; there is no process-name kill or default-session fallback (`scripts/dev-stop:13`). Failed startup retains the reservation for explicit cleanup (`scripts/dev:25`).

## Plan corrections and verification limits

Plan 7.5.3's renderer gate fails: independent per-card font/zoom is not currently available; stop before implementing window-mode scaling. The plan's tab mapping and source-level parent assumption hold, but parked terminals show that tabs are not required for core lifetime (`src/window.rs:3114`). Plan 8.3's clipboard fallback is unnecessary for internal input (`src/hc.rs:512`). App/core isolation is supported by source; real-window isolation acceptance and installed core compatibility remain unverified. The three-file task limit prevents adding these findings to plan section 13. Network features have not been removed: app startup still starts telemetry and updates (`src/main.rs:149`); a debug binary is outside the updater's installed-root detection (`src/update.rs:34`), but this task does not establish zero outbound traffic.

Checks: `bash -n` passed for both scripts. Assert-based checks exercised bad arguments, relative TMPDIR rejection and stop without a reservation, without invoking hc or the app. Executable bits and explicit isolation variables were checked. Ponytail review covered the scripts and connected startup/stop paths; no remaining findings for the source-only scope. No shortcut debt was found in the repository scan (build output, dependencies and the unrelated old web tree excluded). Live startup, actual socket creation and shutdown remain untested.

## Phase 1 changes

Canopy defaults to ~/.config/canopy (or XDG_CONFIG_HOME/canopy); HERDR_APP_HOME still overrides it. The binary is target/debug/canopy. Telemetry, updater, release-note fetching and feedback modules and host APIs are removed. Core discovery remains; setup only gives manual install instructions or chooses an existing binary. No core installer or updater is executed by Canopy. The orchestrator must verify live UI and traffic.
